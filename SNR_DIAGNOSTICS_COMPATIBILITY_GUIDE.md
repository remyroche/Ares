# SNR Diagnostics CLI - Compatibility Guide & Usage Instructions

## Overview

The SNR Diagnostics CLI provides diagnostic tools for analyzing **meta-labeling** output quality, learnability, and model robustness. It works exclusively with artifacts generated by the **feature_generation_meta_labeling_step**.

---

## Compatibility Review

### Meta-Labeling Step Integration

**Investigation Date**: 2025-11-18

#### 1. Artifact Storage

The CLI expects artifacts in the standard Ares artifact directory structure:

**Expected Files**:
```
artifacts/
└── pre_training/
    └── long/
        └── Analyst/  (or Tactician)
            └── feature_generation_labeling_integration_step/
                └── feature_generation_labeling_integration_step_labeled_data_{symbol}_{timeframe}_long_Analyst_{timestamp}.parquet
```

**Naming Convention**:
- Labeled data: `*labeled_data*{symbol}*{timeframe}*.parquet`
- **Note**: Models are NOT loaded from artifacts - fresh models are always trained for diagnostics

#### 2. Expected Data Schema

**Label Column** (one of):
- `meta_label` (primary)
- `label` (alternative)
- `target` (fallback)

**Required Data**:
- Features: All numeric columns (excluding label and market data columns)
- Samples: At least 100+ labeled samples for robust diagnostics
- Target: Continuous values (regression) for meta-labels

**Excluded Columns** (not used as features):
- `meta_label`, `label`, `target`
- `timestamp`, `close`, `open`, `high`, `low`, `volume`
- `realized_return`, `smoothed_label`, `binary_label`, `exit_reason`

## How to Call the CLI

### Prerequisites

**1. Ensure Meta-Labeling Has Run**

The meta-labeling step must complete successfully and generate artifacts:

```bash
# Run your pipeline including meta-labeling step
python -m src.training.launchers.your_launcher --step feature_generation_meta_labeling
```

**2. Verify Artifacts Exist**

```bash
# Check for labeled data files
find artifacts -name "*labeled_data*.parquet" -type f

# Should see files like:
# artifacts/pre_training/long/Analyst/.../labeled_data_ETHUSDT_15m_long_Analyst_20251118_120000.parquet
```

```bash

chmod +x snr_diagnostics

# Run label quality diagnostics
./snr_diagnostics label-quality --symbol ETHUSDT --timeframe 15m

# Run label learnability diagnostics
./snr_diagnostics label-learnability --symbol ETHUSDT --timeframe 15m

./snr_diagnostics model-robustness --symbol ETHUSDT --timeframe 15m
```

```bash

./snr_diagnostics label-quality --symbol ETHUSDT --timeframe 15m --model-type analyst
./snr_diagnostics label-quality --symbol ETHUSDT --timeframe 15m --model-type tactician
```

## Integration with Pipeline

### Automated Diagnostics After Meta-Labeling

Add to your training script:

```python
import subprocess

def run_meta_label_diagnostics(symbol: str, timeframe: str, model_type: str = 'analyst'):
    """Run SNR diagnostics after meta-labeling step."""

    commands = [
        f"./snr_diagnostics label-quality --symbol {symbol} --timeframe {timeframe} --model-type {model_type}",
        f"./snr_diagnostics label-learnability --symbol {symbol} --timeframe {timeframe} --model-type {model_type}",
        f"./snr_diagnostics model-robustness --symbol {symbol} --timeframe {timeframe} --model-type {model_type}",
    ]

    for cmd in commands:
        print(f"Running: {cmd}")
        result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
        if result.returncode != 0:
            print(f"Error: {result.stderr}")
        else:
            print(f"Success: {result.stdout}")

# Example usage after meta-labeling
run_meta_label_diagnostics("ETHUSDT", "15m", "analyst")
```

### Monitoring and Alerts

Parse CSV reports for automated quality checks:

```python
import pandas as pd

def check_meta_label_quality(report_dir: str):
    """Check diagnostic reports for warning signs."""

    # Load learnability report
    learnability_csv = next(Path(report_dir).glob("label_learnability_*.csv"))
    df = pd.read_csv(learnability_csv)

    issues = []

    # Check R²
    r2_row = df[df['metric'] == 'R²']
    if r2_row['value'].iloc[0] < 0.1:
        issues.append("⚠️ Low R²: Meta-labels may have weak signal")

    # Check p-value
    pval_row = df[df['metric'] == 'Permutation p-value']
    if pval_row['value'].iloc[0] > 0.05:
        issues.append("⚠️ Not statistically significant")

    # Load quality report
    quality_csv = next(Path(report_dir).glob("label_quality_*.csv"))
    df_quality = pd.read_csv(quality_csv)

    # Check aleatoric uncertainty
    aleatoric_row = df_quality[df_quality['metric'].str.contains('Aleatoric')]
    if len(aleatoric_row) > 0 and aleatoric_row['value'].iloc[0] > 0.6:
        issues.append("⚠️ High aleatoric uncertainty: Labels are noisy")

    return issues
```

## Troubleshooting

### Error: "No labeled data found"

**Cause**: Meta-labeling step hasn't generated parquet files

**Solutions**:
1. Run `feature_generation_meta_labeling_step` in your pipeline
2. Check `artifacts/pre_training/long/Analyst/` for parquet files
3. Verify symbol and timeframe match exactly (case-sensitive)

**Debug**:
```bash
# Search for any labeled data
find artifacts -name "*labeled_data*.parquet" -type f

# Check specific symbol/timeframe
find artifacts -name "*ETHUSDT*15m*.parquet" -type f
```

### Error: "No label column found"

**Cause**: Parquet file missing expected label columns

**Solutions**:
1. Verify meta-labeling step completed successfully
2. Check that data has one of: `meta_label`, `label`, or `target` column
3. Re-run meta-labeling step if data schema is incorrect

**Debug**:
```python
import pandas as pd
df = pd.read_parquet("path/to/labeled_data.parquet")
print(df.columns.tolist())  # Should include 'meta_label'
print(df['meta_label'].describe())  # Check label distribution
```

### "Why doesn't the CLI use my pre-trained model?"

**This is by design!** The CLI **never** uses pre-trained models because:

1. **Measures label signal, not model performance**: We want to assess the inherent signal in the meta-labels, not how well a specific model was trained
2. **Ensures fair comparison**: Using the same fresh model config for all diagnostics ensures consistent, comparable results
3. **Avoids train/test contamination**: Pre-trained models may have been trained on different data splits

**What the CLI does instead**:
- Always trains fresh LightGBM models using the **exact same config** as feature_generation_meta_labeling_step
- Uses cross-validation to generate unbiased predictions
- For model comparison diagnostics, trains multiple model families (Linear, RF, GBM, LGBM, MLP) for fair comparison

**LightGBM Config** (matching meta-labeling):
```python
lgb.LGBMRegressor(
    n_estimators=800,
    max_depth=8,
    learning_rate=0.01,
    num_leaves=63,
    min_child_samples=20,
    subsample=0.8,
    colsample_bytree=0.7,
    reg_alpha=0.1,
    reg_lambda=0.2
)
```

### Warning: "Wide confidence intervals"

**Meaning**: Model performance is unstable

**Solutions**:
1. Check if you have enough samples (need 100+)
2. Review feature quality
3. Check for outliers or data quality issues
4. Consider feature engineering improvements

## Best Practices

### 1. Run After Every Meta-Labeling

```bash
# After meta-labeling completes
./snr_diagnostics label-learnability --symbol ETHUSDT --timeframe 15m

# If learnability is good (R² > 0.1, p < 0.05), proceed with full diagnostics
./snr_diagnostics label-quality --symbol ETHUSDT --timeframe 15m
./snr_diagnostics model-robustness --symbol ETHUSDT --timeframe 15m
```

### 2. Set Quality Thresholds

Define minimum acceptable metrics:

```python
QUALITY_THRESHOLDS = {
    'min_r2': 0.10,              # Minimum R² for learnable signal
    'max_pvalue': 0.05,          # Statistical significance threshold
    'min_baseline_improvement': 0.05,  # Beat naive baselines by at least 0.05
    'max_aleatoric_fraction': 0.70,    # Maximum acceptable noise fraction
    'max_ci_width': 0.20         # Maximum CI width for stability
}
```

### 3. Version Control Reports

Track diagnostics over time:

```bash
# Add to git for tracking
git add outcomes/label_learnability_*
git commit -m "Add SNR diagnostics for ETHUSDT 15m - R²=0.32"
```

### 4. Compare Across Symbols/Timeframes

```bash
#!/bin/bash
# Run diagnostics for multiple configurations

for symbol in BTCUSDT ETHUSDT SOLUSDT; do
  for timeframe in 15m 1h 4h; do
    echo "Analyzing $symbol $timeframe..."
    ./snr_diagnostics label-learnability --symbol $symbol --timeframe $timeframe
  done
done
```

## Interpretation Guidelines

### R² (Coefficient of Determination)

| R² Range | Interpretation | Action |
|----------|----------------|--------|
| > 0.40 | Strong signal | Excellent - proceed with confidence |
| 0.20-0.40 | Moderate signal | Good - continue training |
| 0.10-0.20 | Weak signal | Marginal - review features/labels |
| < 0.10 | Very weak signal | Poor - reconsider approach |

### SNR (Signal-to-Noise Ratio)

| SNR | Interpretation | R² Equivalent |
|-----|----------------|---------------|
| > 1.0 | Strong | R² > 0.50 |
| 0.3-1.0 | Moderate | R² = 0.23-0.50 |
| 0.1-0.3 | Weak | R² = 0.09-0.23 |
| < 0.1 | Very weak | R² < 0.09 |

### Aleatoric Uncertainty

| Fraction | Meaning | Improvement Potential |
|----------|---------|----------------------|
| < 40% | Low noise | High - can improve model/features |
| 40-60% | Moderate noise | Medium - incremental improvements |
| 60-80% | High noise | Low - limited by label quality |
| > 80% | Very high noise | Very low - labels are mostly noise |
