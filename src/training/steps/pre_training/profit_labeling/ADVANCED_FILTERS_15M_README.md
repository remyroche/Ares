# Advanced Filters for 15m Timeframe Profit Labeling

This document describes the advanced filtering system implemented for 15-minute timeframe profit labeling, designed to improve label quality and reduce noise in the analyst profit labeller.

## Overview

The advanced filters system provides sophisticated filtering techniques optimized for 15-minute timeframe data to enhance the quality of profit labels generated by the VolatilityAwareMultiHorizonLabeler.

## Key Features

### 1. Bar Efficiency Ratio Filter
- **Purpose**: Measures directional price action vs. choppy conditions
- **Formula**: `efficiency_t = |close_t - open_t| / (high_t - low_t)`
- **Implementation**: Rolling mean over 4-8 bars (1-2 hours)
- **Thresholds**:
  - High efficiency (>0.6): Directional price action
  - Low efficiency (<0.3): Choppy conditions
- **Configuration**: `efficiency_window`, `efficiency_threshold_high`, `efficiency_threshold_low`

### 2. Close-Location Value (CLV) Filter
- **Purpose**: Tracks buying/selling pressure and control
- **Formula**: `CLV_t = (2*close_t - high_t - low_t) / (high_t - low_t)`
- **Implementation**: Rolling mean with volatility check
- **Thresholds**:
  - Sustained positive CLV (>0.2): Bullish control
  - Sustained negative CLV (<-0.2): Bearish control
  - High volatility (>0.5): Avoid when CLV fluctuates rapidly
- **Configuration**: `clv_window`, `clv_threshold_positive`, `clv_threshold_negative`, `clv_volatility_threshold`

### 3. ATR Volatility Ratio Filter
- **Purpose**: Normalizes volatility for adaptive filtering
- **Formula**: `r_t = ATR_short / ATR_long`
- **Implementation**: Short-term (1 hour) vs long-term (5 hours) ATR comparison
- **Thresholds**:
  - Too jumpy (>1.5-2.0): Skip signals
  - Too quiet (<0.5): Skip signals
- **Configuration**: `atr_short_window`, `atr_long_window`, `atr_ratio_threshold_high`, `atr_ratio_threshold_low`

### 4. Trend Coherence Filter
- **Purpose**: Ensures trend continuity and direction consistency
- **Components**:
  - Direction consistency: % of bars closing in same direction within last N bars
  - EMA slope: Rolling slope of EMA for trend continuity
- **Thresholds**:
  - Min direction consistency: 60%
  - Min EMA slope: 0.001
- **Configuration**: `direction_window`, `min_direction_consistency`, `ema_period`, `min_slope_threshold`

## Configuration

### AdvancedFiltersConfig

```python
@dataclass
class AdvancedFiltersConfig:
    # Global enable/disable
    enabled: bool = True
    
    # Bar Efficiency Ratio settings
    enable_efficiency_ratio: bool = True
    efficiency_window: int = 6  # Rolling window for efficiency (4-8 bars = 1-2 hours)
    efficiency_threshold_high: float = 0.6  # High efficiency = directional
    efficiency_threshold_low: float = 0.3   # Low efficiency = choppy
    
    # Close-Location Value (CLV) settings
    enable_clv: bool = True
    clv_window: int = 8  # Rolling window for CLV smoothing
    clv_threshold_positive: float = 0.2   # Sustained positive CLV = bullish
    clv_threshold_negative: float = -0.2  # Sustained negative CLV = bearish
    clv_volatility_threshold: float = 0.5  # Avoid when CLV fluctuates rapidly
    
    # ATR Volatility Ratio settings
    enable_atr_ratio: bool = True
    atr_short_window: int = 4   # Short-term ATR window (1 hour)
    atr_long_window: int = 20   # Long-term ATR window (5 hours)
    atr_ratio_threshold_high: float = 1.5  # Too jumpy
    atr_ratio_threshold_low: float = 0.5   # Too quiet
    
    # Trend Coherence settings
    enable_trend_coherence: bool = True
    direction_window: int = 8   # Window for direction consistency check
    min_direction_consistency: float = 0.6  # 60% of bars in same direction
    ema_period: int = 12        # EMA period for slope calculation
    min_slope_threshold: float = 0.001  # Minimum slope for trend continuity
    
    # Combined filtering
    filter_type: FilterType = FilterType.COMBINED
    min_eligibility_ratio: float = 0.3  # Minimum ratio of eligible samples
    strict_mode: bool = False  # Use strict eligibility criteria
    
    # Quality checks
    min_eligible_samples: int = 50
    max_filter_failure_rate: float = 0.7  # Maximum allowed filter failure rate
```

## Usage

### Basic Usage

```python
from src.training.steps.pre_training.profit_labeling.advanced_filters_15m import (
    AdvancedFilters15m,
    AdvancedFiltersConfig,
    apply_advanced_filters_15m
)

# Create sample 15m OHLCV data
data = pd.DataFrame({
    'open': [...],
    'high': [...],
    'low': [...],
    'close': [...],
    'volume': [...]
})

# Apply filters with default configuration
result = apply_advanced_filters_15m(data)

# Check results
print(f"Eligibility ratio: {result.eligibility_ratio:.1%}")
print(f"Eligible samples: {result.n_eligible_samples}/{result.n_total_samples}")
```

### Custom Configuration

```python
# Create custom configuration
config = AdvancedFiltersConfig(
    efficiency_threshold_high=0.7,
    efficiency_threshold_low=0.4,
    clv_threshold_positive=0.3,
    clv_threshold_negative=-0.3,
    atr_ratio_threshold_high=1.3,
    atr_ratio_threshold_low=0.6,
    min_direction_consistency=0.7
)

# Apply filters with custom configuration
filter_system = AdvancedFilters15m(config)
result = filter_system.apply_filters(data)
```

## Filter Results

### FilterResult

The filtering system returns a `FilterResult` object containing:

- **Core Results**:
  - `eligibility_mask`: Boolean Series indicating which samples passed all filters
  - `eligibility_ratio`: Percentage of samples that passed all filters
  - `n_eligible_samples`: Number of samples that passed all filters
  - `n_total_samples`: Total number of input samples

- **Filter-Specific Results**:
  - `efficiency_mask`: Results from efficiency ratio filter
  - `clv_mask`: Results from CLV filter
  - `atr_ratio_mask`: Results from ATR ratio filter
  - `trend_coherence_mask`: Results from trend coherence filter

- **Statistics**:
  - `filter_statistics`: Detailed statistics for each filter
  - `filter_effectiveness`: Effectiveness ratio for each filter
  - `overall_quality_score`: Overall quality score (0.0-1.0)
  - `noise_reduction_ratio`: Percentage of samples filtered out

## Performance Considerations

### Memory Usage
- The filters are optimized for 15m timeframe data
- Rolling calculations are vectorized for efficiency
- Memory usage scales linearly with data size

### Processing Time
- Typical processing time: ~0.05s for 500 samples
- Scales approximately O(n) with data size
- Parallel processing available for large datasets

### Quality Metrics
- Filter effectiveness typically ranges from 20-80% depending on market conditions
- Combined filters use AND logic (all filters must pass)
- Quality score combines eligibility ratio and noise reduction

## Best Practices

### 1. Data Requirements
- Minimum 50 samples recommended for reliable filtering
- Ensure OHLCV data has valid relationships (high >= low, etc.)
- Handle missing data appropriately before applying filters

### 2. Configuration Tuning
- Start with default settings and adjust based on market conditions
- Monitor filter effectiveness and adjust thresholds accordingly
- Use stricter settings for higher quality but fewer samples

### 3. Integration
- Apply filters before profit labeling for best results
- Consider market regime when configuring filters
- Monitor label quality after filtering

## Troubleshooting

### Common Issues

1. **Low Eligibility Ratio**: Adjust filter thresholds to be more lenient
2. **High Filter Failure Rate**: Check data quality and filter configuration
3. **Insufficient Samples**: Increase data size or relax filter criteria

### Debug Information

The system provides detailed logging and statistics:
- Individual filter pass rates
- Filter effectiveness metrics
- Quality scores and warnings
- Processing time and memory usage
