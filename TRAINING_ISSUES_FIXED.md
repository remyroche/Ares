# Training Issues Fixed - 2025-11-09

## Issues Addressed

### 1. ✅ Feature Mismatch (60 vs 64 features)
**Problem:** Model trained with 64 features (60 base + 4 engineered) but post-HPO validation used 60 features.

**Root Cause:** 
- `_train_single_model()` engineered features internally (adding 4 regime confidence features)
- Post-HPO metrics collection received original data without engineered features
- Model expected 64 features but got 60 → Fatal error

**Fix:**
- Modified `_train_single_model()` to store engineered data in `TrainingResult.metadata['engineered_data']`
- Updated metrics collection to use engineered data: `data_for_metrics = model_result.metadata.get('engineered_data', processed_data)`
- Ensures consistency between training and validation feature sets

**Files Modified:**
- `src/training/steps/models_training/core/model_trainer.py` (lines 267-308, 179-193)

### 2. ✅ Empty Array Error During HPO
**Problem:** `Found array with 0 sample(s) (shape=(0, 22)) while a minimum of 1 is required`

**Root Cause:**
- In light execution mode, datasets are very small (< 30 samples)
- Cross-validation with 3 folds on tiny datasets created empty folds
- HPO tried to predict on empty arrays
- Default cross-validation without shuffle could create sequential empty folds

**Fix (Two-Layer Defense):**

**Layer 1 - Pre-HPO Validation:**
- Added dataset size validation before HPO starts
- Skip HPO if dataset < 10 samples
- Dynamically adjust CV folds: `cv_folds = min(3, max(2, len(data) // 5))`
- Ensures at least 5 samples per fold

**Layer 2 - Robust HPO Objective Function:**
- Use `KFold` with `shuffle=True` to avoid sequential empty folds
- Filter out invalid scores (NaN, Inf) before averaging
- Enhanced error logging to distinguish empty fold errors
- Graceful degradation: return very bad score (-999999) instead of crashing

**Files Modified:**
- `src/training/steps/models_training/core/model_trainer.py` (lines 356-399)

### 3. ✅ LightGBM "No More Leaves" Warning
**Problem:** `[LightGBM] [Warning] Stopped training because there are no more leaves that meet the split requirements`

**Root Cause:**
- Default parameters (num_leaves=255, max_depth=8, min_child_samples=20) too aggressive for small datasets
- With < 100 samples, tree couldn't create enough valid splits

**Fix:**
- Added dynamic parameter adjustment for small datasets (< 100 samples):
  - `min_child_samples = max(1, min(min_child_samples, n_samples // 10))`
  - `num_leaves = min(num_leaves, max(7, n_samples // 3))`
  - `max_depth = min(max_depth, 5)`
- Logs adjusted parameters for transparency

**Files Modified:**
- `src/training/steps/models_training/core/model_trainer.py` (lines 493-501)

### 4. ✅ Missing Regime Probabilities
**Problem:** `No regime probabilities provided or found in data, using uniform distribution`

**Root Cause:**
- Regime probabilities ARE generated by `regime_ensemble_training` and stored in HDF5
- However, they were only being loaded for ensemble and tactician_base training
- analyst_base training was NOT loading regime probabilities
- Feature engineer correctly fell back to uniform distribution

**Fix:**
- Modified condition to load regime probabilities for ALL training types
- Changed: `if training_type.endswith('ensemble') or training_type == 'tactician_base':`
- To: `if training_type in ['analyst_base', 'tactician_base', 'analyst_ensemble', 'tactician_ensemble']:`
- Now analyst_base will receive regime probabilities from HDF5

**Files Modified:**
- `src/training/steps/model_training/unified_models_training_step.py` (line 216)

**Note:** The regime probabilities loading logic (lines 2125-2174) already loads for all training types - we just needed to call it for analyst_base too.
