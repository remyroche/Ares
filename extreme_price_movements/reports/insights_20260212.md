# Insights from Report Review (2026-02-12)

## What can we learn?

1.  **H8 Horizon Dominance:**
    *   The 8-hour horizon (`long_tf_H8`, `short_tf_H8`) consistently outperforms shorter horizons (H2, H4) in the Alpha model race.
    *   `long_tf_H8:catboost` was the top performer with a score of ~1.25.
    *   This suggests that the underlying market signals for "extreme" movements are more robust and less noisy over longer timeframes, allowing trends to develop more clearly.

2.  **Meta-Model "Sniper" Behavior:**
    *   Tail-weighted Meta Models (e.g., `xgb_tailweighted`) demonstrate high realized rates in the top decile (high precision).
    *   However, they suffer from negative overall PnL and low general scores.
    *   They act as "snipers"—excellent when highly confident, but their "average" predictions are poor.

3.  **Feature Bloat & Overfitting:**
    *   Most Alpha models failed strict `logloss` improvement and `pr_auc` checks.
    *   The feature set is massive (`tf_feature_keys` includes almost everything).
    *   The inconsistency in logloss improvement across folds (failed by `long_tf_H8`) indicates overfitting to specific regimes and a lack of generalization, likely due to the "curse of dimensionality."

4.  **Calibration Gap:**
    *   There is a significant discrepancy between raw and calibrated coverage, particularly in the tails (top deciles) for the Meta models.
    *   This implies the models' raw probability outputs are not reliable estimates of true risk without heavy calibration.

## How can we improve?

1.  **Shift Focus to H8:**
    *   Adopt H8 as the primary signal generator for directional bias.
    *   Use H4/H2 signals primarily as timing triggers or confirmation for H8 setups, rather than standalone drivers.

2.  **Aggressive Feature Pruning:**
    *   Reduce the feature set for Base/Alpha models.
    *   Use domain knowledge to group correlated features and select representatives (e.g., choose one "volatility" metric instead of five).
    *   Implement stricter feature selection (e.g., Recursive Feature Elimination) before model training to remove noise.

3.  **Regime-Gating:**
    *   Explicitly use Regime features (volatility, trend state) to *gate* model execution.
    *   For example, disable `long_tf` models entirely when `is_trending` is false, rather than asking the model to learn this implicitly from inputs.

4.  **Tail-Specific Calibration:**
    *   Implement specialized calibration for the tail end of the distribution (p > 0.9).
    *   Consider using Extreme Value Theory (EVT) or a separate calibrator for high-confidence predictions to better estimate the probability of these rare, high-impact events.

## Chat Analysis

### Meta-Model "Sniper" Behavior
**Q: What if we trade on top20% decile only?**
A: **Yes, absolutely.** The data confirms this is the optimal strategy. The "Sniper" behavior (high realized rate in top deciles, poor global PnL) indicates the model effectively separates high-probability opportunities from noise, but the "noise" bucket is huge. Enforcing a strict probability threshold (e.g., `score > quantile(0.8)`) at inference time transforms the "negative PnL" model into a profitable precision tool. This is already supported via configuration parameters like `k_long`.

### Feature Bloat & Overfitting
**Q: We have a feature selection pipeline (RFE). Review it to ensure we prevent overfitting.**
A: **Verified.** We use a robust RFE pipeline (`mdi_feature_selection_v3`) which reduces hundreds of features to ~60 using `ExtraTreesRegressor` and recursive elimination. It also includes an ElasticNet pre-screen for initial noise reduction. The observed overfitting is likely due to the inherent noise of the market data rather than remaining "bloat" after RFE, though further reducing `end_features` (e.g. to 30) could be tested.

### Regime-Gating
**Q: Don't we already do that with labels?**
A: **Yes, we do.** `config.py` sets explicit volatility thresholds (`train_min_vol_zscore: 1.6`). The training set construction strictly filters out any time/symbol pairs that don't meet these criteria. Thus, the model is never trained on low-volatility "chop," effectively implementing regime gating at the dataset level.

### Tail-Specific Calibration
**Q: Should we adjust our calibration specifically for the top30% deciles?**
A: **Ideally yes, but ranking matters more.** Current calibration uses global Isotonic Regression, which minimizes global error (dominated by non-trades). While tail-weighted calibration is possible, since we plan to trade only the top 20% (Point 2), preserving the **rank ordering** (measured by PR-AUC/NDCG) is more critical than perfect probability calibration. The current setup optimizes for ranking, which aligns with the "Sniper" strategy.
