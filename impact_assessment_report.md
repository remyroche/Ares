# Impact Assessment Strategy: Layer 0 & 1 on Downstream Performance (Revised v2)

## Executive Summary

This revised strategy proposes a **Targeted Diagnostics Script** (`scripts/assess_layer_impact.py`) designed to measure the specific value-add of Layer 0 (Noise Filtering) and Layer 1 (Sample Weighting).

**Key Design Principles:**
1.  **Lightweight:** Instead of running full HPO (heavy), we analyze the impact on a fixed set of **"Winning Geometries"** (derived from a baseline run or provided config).
2.  **Component-Aware:** We decompose Layer 1 into its constituent parts (Magnitude, Uniqueness, Consistency, Quality, Risk, Time) to attribute value.
3.  **Noise-Focused:** We assess Layer 0's ability to filter noise and stabilize the pricing signals used by Layer 2.

---

## 1. Layer 0 Assessment: Signal Processing & Noise Filtering

**Objective:** Quantify how Kalman Smoothing and VWAP (Layer 0) affect the quality of inputs fed into the Winning Geometries.

**Methodology:**
1.  **Input Comparison:**
    *   Compare `Raw Close` vs. `Kalman Price` (L0 Output).
    *   Compare `Raw Volatility` vs. `Kalman Volatility` (L0 Output).
2.  **Barrier Simulation (Fixed Geometries):**
    *   Run the "Winning Geometries" (TP/SL/Horizon) using **Raw** data.
    *   Run the same Geometries using **Smoothed** data (replacing `close` with `kalman_price` for barrier checks).
    *   *Note: This checks if "noise" caused premature stop-outs or missed entries.*

**Key Metrics:**
*   **Noise Reduction Ratio:** `StdDev(Raw_Returns) / StdDev(Kalman_Returns)`. Higher is better (if > 1).
*   **Whipsaw Reduction:** Count of events where `Raw` hit SL but `Smoothed` did not (false positives triggered by noise).
*   **Volatility Stability:** Variance of the dynamic barrier width (`k * Volatility`). Smoother volatility implies more predictable barriers.

## 2. Layer 1 Assessment: Weighting Component Decomposition

**Objective:** Decompose the "Black Box" of Sample Weights to see which factors drive performance.

**Methodology:**
For the events generated by the Winning Geometries, we compute sample weights under **8 distinct schemes** to isolate each component:

1.  **Baseline:** Uniform Weights ($w = 1.0$).
2.  **Magnitude Only:** Weights driven by absolute returns (optionally volatility-normalized).
3.  **Uniqueness Only:** Weights penalized by concurrency/overlap.
4.  **Consistency Only:** Weights boosted by label stability/agreement.
5.  **Quality Only:** Weights derived from Confident Learning scores (out-of-sample probability).
6.  **Risk Only:** Weights penalized by high volatility (downside multiplier).
7.  **Time/Decay Only:** Weights driven by recency (Sigmoid or Exponential Decay).
8.  **Full Composite:** The production L1 formula combining all active components.

**Key Metrics per Scheme:**
*   **Information Coefficient (IC):** Correlation between `Weight` and `Future_Return` (or `Target_Label`). Does the weight actually predict quality?
*   **Effective Sample Size (ESS):** `(Σw)^2 / Σ(w^2)`. Measures how much data we "lose" by weighting.
*   **Class Separation:** Difference in mean weight between `Winners` and `Losers`.
    *   *Goal:* We want Winners to have significantly higher weights than Losers.
*   **Stability:** Variance of weights over time.

## 3. Implementation Plan: `scripts/assess_layer_impact.py`

The script will operate in three phases:

### Phase A: Setup
1.  Load `market_data` (Parquet).
2.  Load/Define **Winning Geometries** (JSON config or simple default set).
3.  Generate `Events` (timestamps) using the Winning Geometries on the Baseline data.

### Phase B: Layer 0 Diagnostics (Noise)
1.  Compute `Kalman/VWAP` features (Layer 0 logic).
2.  Calculate **Noise Metrics** (Diffs, variances) between Raw and Smoothed.
3.  Simulate "Alternate Reality" outcomes for the events using Smoothed prices.
    *   *Output:* "Noise Cost" (PnL lost to noise).

### Phase C: Layer 1 Diagnostics (Weights)
1.  Calculate all 8 weighting schemes for the generated events.
2.  Compute **Component Impact Table**:
    *   Columns: `Scheme`, `IC`, `ESS`, `Winner_Weight_Mean`, `Loser_Weight_Mean`.
3.  *Optional L3 Proxy:* Train a lightweight Linear Probe using each weighting scheme and report `OOF AUC`.
